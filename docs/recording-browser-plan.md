# 0.3 录音清单与文字稿性能

本次针对排序、搜索和文字稿打开慢。现有清单仅按文件名搜索，没有排序入口；详情每次重新读 TXT，并用单个 SwiftUI Text 排版全文。启动时还会等待全部媒体复核后才显示记录。

实现范围：

- 原生表格，列标题和明确的排序菜单均可排序；支持名称、导入时间、大小、设备及状态，默认最近导入。
- 单独的醒目搜索栏，默认查询文件名、设备及文字稿正文；支持中文短词。正文索引保存在本机，首次按需建立，显示进度；后续复用并增量更新。
- 文字稿后台读取、限量内存缓存、快速切换防串稿；长文改用原生 NSTextView 延迟排版，显示加载、缺失与刷新入口。
- 清单先显示，启动不再扫描全部已有音频，媒体检查保留在实际导入与转写之前；不再在主线程初始化大录音库，也不在无恢复任务时重写历史文件。
- 保留工具版与引导版。提供使用工具版原数据目录的兼容更新包；原 `.app` 不覆盖，原录音不移动。

验证使用合成数据：中文查询、自然名称排序、升降序、状态筛选、索引更新与重启、缺失 TXT 的 Markdown 回退、缓存复用、刷新、长文预览上限、快速切换和大规模清单。界面已用合成测试库验证，结果和限制见 [验证记录](recording-browser-verification.md)。真实录音只作本机只读诊断，不进入提交或构建包。
